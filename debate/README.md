# 两边之间

一个为 6–8 人小型团契设计的信仰价值张力讨论页面。活动不评判输赢，也不要求参与者公开自己的真实立场；大家会暂时代言一个观点，理解它所保护的价值，再通过逐步变化的情境寻找条件、界线与整合方向。

页面由一台投影电脑主持，不需要参与者使用手机，也没有账号、后端、计分或联网数据。

## 活动流程

1. 全组从十个问题中口头商量并选择一题。
2. 主持人输入 6–8 个名字，页面随机分成两组并分配立场。
3. 每人获得一个轻量的思考镜头：经文观察、现实影响、边界风险或同理理解。
4. 两组分别准备本方的合理理由；需要时可展开经文入口。
5. 两组依次分享，不计分，也不选获胜方。
6. 逐张揭示三个只改变单一条件的情境，两组重新判断原论点需要增加什么条件。
7. 阵营结束，全组围绕关键变量自由交流。
8. 查看预先整理的全局观点地图、经文与延伸来源。

页面只显示柔和的建议时间，不倒数、不响铃，也不会自动切换阶段。主持人使用底部按钮或键盘左右方向键推进。

## 文件结构

```text
debate/
├─ index.html   # 页面入口和固定外壳
├─ styles.css   # 投影布局、响应式样式与视觉主题
├─ app.js       # 分组、角色、阶段导航和本地状态
├─ topics.js    # 十个主题的全部讨论内容
└─ README.md    # 项目说明
```

## 题目内容

每个主题在 `topics.js` 中包含：

- 两种立场的名称与公平表述
- 至少三处经文入口及阅读提示
- 三个每次只改变一个条件的情境变量
- 敏感话题的主持安全提醒
- 常见基督徒思路、双方优势与极端风险
- 关键变量、整合方向与仍未消除的张力
- 可继续阅读的外部来源

修改或新增题目时，应保持双方均采用其支持者能够认可的语言。经文用于照亮价值张力，不应简单标成某一方的“武器”。情境卡也不应通过隐瞒信息或极端悲剧强迫参与者反转。

## 分组与角色

- 6 人会分成 3 + 3，8 人会分成 4 + 4，7 人会分成 4 + 3。
- 四人组使用四个独立思考镜头。
- 三人组会把“现实影响”与“同理理解”合并。
- 随机分组后，可以先点击一名成员的“选择交换”，再点击另一组的一名成员完成互换。
- 角色只是观察角度，不是正式辩论的一辩、二辩，也不规定发言顺序。

## 状态保存

主题、名单、分组、角色、当前阶段和经文展开状态都保存在当前浏览器的 `localStorage` 中，key 是：

```text
pnyl-between-sides-v1
```

刷新页面会恢复当晚进度。换浏览器或换电脑不会同步。右上角“重新开始”会先要求确认，再清除本机活动状态。

页面不会保存或上传参与者的真实倾向；真实立场始终只留在参与者心里。

## 本地运行

页面使用原生 ES modules，建议通过本地静态服务器运行，而不是直接双击文件：

```powershell
cd C:\Users\ducenhan\Desktop\信仰大富翁
python -m http.server 8765
```

然后打开：

```text
http://127.0.0.1:8765/debate/
```

也可以随现有父项目直接发布到 Netlify 或其他静态站点服务。公开路径为 `/debate/`，父目录的 `index.html` 已包含入口。

## 现场使用建议

1. 活动前在投影电脑打开页面并测试全屏显示。
2. 提前浏览当晚可能选择的题目、经文和安全提醒。
3. 正式开始前点击“重新开始”，避免恢复上一次的名单和进度。
4. 随机分组后检查表达能力是否过度集中，必要时交换成员。
5. 变量阶段一次只揭示一张卡，不要提前透露后面的变化。
6. 遇到饶恕、心理健康或家庭边界等题目，不要求成员公开创伤、病史或家庭隐私。
7. 总结页是一张观点地图，不应被主持人读成唯一标准答案。

## 非目标

- 不做比赛、计分、投票、排行榜或胜负判定。
- 不收集个人真实立场或活动后的个人反思。
- 不做账号、多人同步、云端房间或长期讨论记录。
- 不用现成论据取代参与者的思考；准备阶段只提供可选经文入口。
