# 两边之间

这是一个给小型团契使用的共同案例讨论页面。每个题目都保留两股真实拉力，但参与者不会被分队，也不会被随机分配观点。大家先面对同一个虚构案例，只说自己真正怎么判断，再看看新情况和经文会不会改变想法。

页面由一台投影电脑主持，不需要参与者使用手机，也没有账号、后端、计分或联网数据。至少 2 人即可开始，6–8 人通常最舒服。

## 活动流程

1. 全组从十个两难问题中选择一题。
2. 主持人输入参与者名单。
3. 页面显示共同虚构案例，并随机给每个人一张很小的参与任务。任务不代表立场，可以随时换一张。
4. 大家回答同一个问题：“如果你是案例中的人，你下一步会怎么做？为什么？”
5. 页面逐一显示三个“情况变化”。每次只增加一个新事实，再问判断是否改变。
6. 第一轮讨论结束后再读经文，思考经文肯定和修正了哪些想法。
7. 最后只显示两种常见考虑，不给标准答案，也不要求达成一致。

页面显示柔和的建议时间，不倒数、不响铃，也不会自动切换阶段。主持人使用底部按钮或键盘左右方向键推进。

## 参与任务

页面使用五种任务：

- **说出判断**：说“我目前会……，因为……”。
- **问清理由**：追问“你为什么把……看得很重要？”。
- **说出改变条件**：说“如果……，我的答案会／不会改变。”。
- **读经文提醒**：读经后说“这段经文让我注意到……”。
- **听完总结**：最后说“我听到一个值得继续想的点是……”。

发任务时会先打乱一整组任务，人数超过五人后才开始重复。点击参与者卡片上的“换一张”，可以随机换成另一种任务，不需要解释。

任务只要求一句话，不规定发言顺序，也不会公开记录谁已完成。完成任务后仍可自由参与其他部分。

## 题目内容

每个主题在 topics.js 中包含：

- 选题页问题和两股拉力
- 一个具名、虚构的共同案例
- 一个明确的下一步行动问题
- 三个每次只改变一个事实的情况变化
- 三处经文及不站队的阅读提示
- 两种常见考虑
- 必要的主持安全提醒

案例不依赖参与者拥有相同的工作、婚姻、家庭或服事经历。成员可以只讨论虚构人物，不需要分享私人经历。

经文放在第一轮讨论之后。它不是用来替某一边寻找证据，而是帮助大家检查、补充和修正刚才的判断。

## 状态保存

选题、名单、任务、当前阶段和情况变化都保存在当前浏览器的 localStorage 中，key 是 pnyl-between-sides-v2。

刷新页面会恢复当晚进度。换浏览器或换电脑不会同步。右上角“重新开始”会先要求确认，再清除本机活动状态。

## 本地运行

页面使用原生 ES modules，建议通过本地静态服务器运行：

也可以随父项目直接发布到 Netlify 或其他静态站点服务。公开路径为 /debate/。

## 现场使用建议

1. 活动前提前看一遍可能选择的案例、经文和安全提醒。
2. 正式开始前点击“重新开始”，避免恢复上一次的名单与进度。
3. 先确认大家都听懂案例，再开始发言。
4. 不点名要求成员分享自己的类似经历。
5. 情况变化一次只讨论一张，不提前把三个变化混在一起。
6. 如果现场观点完全一致，不需要制造反方；可以继续讨论这个共识在什么情况下会改变。
7. 总结页只是两种常见考虑，不是小组应当接受的结论。

## 这个页面不会做什么

- 不随机分配观点，也不要求替自己不认同的立场辩护。
- 不分队、不计分、不投票，也不选获胜方。
- 不要求每个人公开私人经历。
- 不收集个人立场或活动后的反思。
- 不做账号、多人同步、云端房间或长期记录。
- 不用预写总结宣布标准答案。
