# 两边之间

这是一个给小型团契使用的自由选边辩论页面。每个题目都有明确的 A、B 两方，但参与者不会被随机分配观点。大家选择自己真正支持的一方，围绕该方主张给理由、回应另一方，也可以在讨论中换边。

页面由一台投影电脑主持，不需要参与者使用手机，也没有账号、后端、计分或联网数据。至少 2 人即可开始，6–8 人通常最舒服。

## 活动流程

1. 全组从十个两难问题中选择一题。
2. 主持人输入参与者名单。
3. 页面明确显示 A、B 两方。每个人在自己的任务卡上自由选边，并随机领取一个围绕立场发言的小任务；任务可以随时换一张。
4. A、B 两方轮流陈述，每次只讲一个与本方主张直接有关的理由。两方论点下会持续显示当前站在这一方的人，讨论中可以换边。
5. 第二轮先回应另一方。若题目太抽象，可以点击“显示具体案例”，再围绕案例和三个单一变化继续辩论；不需要案例时可以保持收起。
6. 最后再次并排显示双方立场，不给标准答案，也不要求达成一致。

页面显示柔和的建议时间，不倒数、不响铃，也不会自动切换阶段。主持人使用底部按钮或键盘左右方向键推进。

## 参与任务

页面使用五种任务：

- **给出一个理由**：替所选一方说出一个尚未出现的理由。
- **回应另一方**：直接回应另一方刚才的一条理由。
- **问另一方一个问题**：用问题听懂理由，不急着反驳。
- **说出换边条件**：说明什么新情况会让自己考虑换边。
- **说出本方代价**：说出所选一方需要承担的一个代价或风险。

发任务时会先打乱一整组任务，人数超过五人后才开始重复。点击参与者卡片上的“换一张”，可以随机换成另一种任务，不需要解释。

任务卡在投影和桌面上排成两列，并提供“站 A 方”“站 B 方”和“暂不选边”；窄屏会改为一列。任务只要求一句话，不规定发言顺序，也不会公开记录谁已完成。完成任务后仍可自由参与其他部分。

从自由选边页到最终总结页，两个论点下都会显示各方当前成员。点击姓名旁的“换到 A／B”即可调整；尚未选边的人会单独保留，不会被强制分配。

## 题目内容

每个主题在 topics.js 中包含：

- 选题页问题和两个明确立场
- 一个默认收起、按需显示的具名虚构案例
- 一个围绕原 A、B 两方的案例站队问题
- 三个每次只改变一个事实的情况变化
- 支持两方各自最重要的一组考虑
- 必要的主持安全提醒

案例不依赖参与者拥有相同的工作、婚姻、家庭或服事经历。题目本身够清楚时可以完全不用案例；需要更具体时再显示。成员可以只讨论虚构人物，不需要分享私人经历。

## 状态保存

选题、名单、任务、当前站队、当前阶段、案例是否展开和情况变化都保存在当前浏览器的 localStorage 中，key 是 pnyl-between-sides-v3。

刷新页面会恢复当晚进度。换浏览器或换电脑不会同步。右上角“重新开始”会先要求确认，再清除本机活动状态。

## 本地运行

## 现场使用建议

1. 活动前提前看一遍可能选择的两方立场、案例和安全提醒。
2. 正式开始前点击“重新开始”，避免恢复上一次的名单与进度。
3. 先确认大家都听懂两方分别主张什么，再开始自由选边。
4. 不点名要求成员分享自己的类似经历。
5. 只有在题目太抽象时才显示案例；情况变化一次只讨论一张。
6. 如果一方暂时没人，不需要制造反方；可以讨论什么情况会让人换边。
7. 总结页只是并排重申双方立场，不是小组应当接受的结论。

## 这个页面不会做什么

- 不随机分配观点，也不要求替自己不认同的立场辩护。
- 不强迫两边人数相等，不计分，也不选获胜方。
- 不要求每个人公开私人经历。
- 不上传个人立场，也不保存活动后的反思。
- 不做账号、多人同步、云端房间或长期记录。
- 不用预写总结宣布标准答案。
