# 两边之间

这是一个给团契使用的扫码选题与自主站队辩论网站。十道题采用接近《奇葩说》的表达方式：问题短、冲突清楚、个人需要付出代价，两边都保护一种值得认真对待的价值，也都有真实支持者。

生产地址：<https://debate.ducenhan.com/>

## 现场流程

1. 主持人在投影打开网站，页面自动建立一个 6 小时有效的房间，并显示二维码和六位房间码。
2. 参与者扫码，在不填写昵称的情况下，从十道辩论题目中匿名多选所有感兴趣的题。
3. 投影只显示每道题的兴趣总数和当前最高兴趣题，不显示也不保存「谁选了什么」。人数到齐后，主持人点击「进入主题选择」，再根据汇总结果决定今晚的题目。
4. 主持人定题后，手机才会要求填写昵称并一次性选择 A／B 立场；提交后不能换边，同一昵称会被拒绝。
5. 主持人确认所有人都选完边后统一发放隐藏任务。参与者需要在自己手机上点击揭晓；任务不会出现在投影或主持接口返回的数据中。
6. 辩论开始后仍可扫码加入：迟到者直接填写昵称、选择一边，并立即获得个人任务。双方人数可以不同。
7. 投影只显示两方主张与圆形昵称头像，主持人可以移除误填或重复加入的成员，并依次推进双方陈述、回应或案例、最后看两边。

主屏每 2.2 秒读取一次房间状态。手机也用相同频率等待选题或阶段变化，所以不需要参与者刷新页面。

主持页右上角的「演示流程」会在当前浏览器中载入示例票数和八位虚拟参与者，方便没有真人时预览每个阶段。演示数据不会写入 D1，也不会改变真实房间；退出演示后，页面会重新读取真实房间状态。

## 十道辩题

- 基督徒做重大决定时，应该等到心里「有平安」再行动，还是根据现有信息先作决定？
- 一件事祷告了很久仍没有回应，我该继续求，还是学会放下？
- 好朋友说「别再跟我谈信仰」，我还要不要继续找机会开口？
- 教会里出现冲突，应该优先私下处理、保护合一，还是尽早公开讨论、避免问题被掩盖？
- 团契里有人一直不发言，带领者应该点名邀请，还是尊重他保持沉默？
- 基督徒在职场受到不公平对待，应该愿意吃亏，还是明确为自己争取？
- 教会服事已经让我长期疲惫，我该把坚持当作忠心，还是主动暂停？
- 升职关键期需要连续三个月周日加班，我该拒绝这份安排，还是接受加班并改在其他时间参与教会生活？
- 家里正为钱发愁，我该暂停固定奉献吗？
- 明知坦白信仰立场可能失去这段感情，我还要不要说？

每题还保留一个可选的具体案例、三个只改变一项事实的变化、双方参考理由、三处经文线索和安全提醒。参考理由只会在回应阶段出现，避免第一轮所有人复述网页答案。

## 手机隐藏任务

目前先放入六种任务机制：经文连接、指出本方弱点、真诚提问、总结对方、具体例子，以及在同队有人时可能出现的「神队友」任务。其中指出本方弱点、真诚提问和总结对方都需要至少完成三次；「神队友」会指定一位同队成员，要求在对方发言后用自己的方式表达赞赏，不限定句式。任务在主持人统一发放后才生成，手机默认遮住内容，参与者点击后才揭晓。这些内容集中在 `public/topics.js`，之后可以继续讨论和替换。

## 数据与隐私

- 一个房间 6 小时后自动过期；定时任务每小时清除过期房间和参与者。
- 匿名选题与实名站队保存在两张独立的数据表中，两者没有关联字段；选题阶段不接收昵称。没有账号，也不保存发言内容。
- 主持人凭证只保存在主持电脑的 `localStorage`；参与者凭证按房间保存在各自手机的 `localStorage`。
- 主持接口不返回任何人的隐藏任务。
- 「新一局」会清除当前房间的匿名票、昵称、站队与任务，但保留同一个二维码房间码，方便现场立即重扫。
- 右上角会一直保留「显示二维码」入口。若主持浏览器状态丢失，可用房间码和管理员恢复码接管仍在 6 小时有效期内的房间；恢复会让旧主持凭证立即失效。

## 文件结构

    debate/
    ├─ public/
    │  ├─ index.html       # 投影主持页
    │  ├─ app.js           # 主持流程、兴趣榜与双方头像
    │  ├─ api.js           # 主持与参与者 API 客户端
    │  ├─ demo.js          # 仅在主持浏览器运行的演示数据与流程
    │  ├─ topics.js        # 十道辩题与隐藏任务
    │  ├─ qr.js            # 本地二维码编码器
    │  ├─ styles.css       # 投影样式
    │  └─ join/            # 手机问卷、选边与任务页
    ├─ src/worker.js       # Cloudflare Worker API
    ├─ test/               # 题库、二维码与校验测试
    ├─ schema.sql          # D1 数据表
    ├─ wrangler.jsonc      # Worker、静态资源与域名配置
    └─ package.json

仓库根目录的 `debate/index.html` 只是给 PNYL 静态首页使用的生产地址跳转页；Worker 实际提供的是 `debate/public/`。

## 本地运行

当前项目使用独立的 `pnyl-debate` D1 数据库和四张 `debate_*` 数据表，不会读写其他活动的数据。

    cd C:\Users\ducenhan\Desktop\信仰大富翁\debate
    npm install
    npm run db:local
    npm run dev

本地管理员恢复码放在不会提交到 Git 的 `.dev.vars` 中；复制 `.dev.vars.example` 可以配置另一套本地环境。

Wrangler 默认会显示本地地址。打开主持页后，用同一网络可访问该地址的手机扫码；只在同一台电脑测试时，也可以直接打开 `/join/?room=房间码`。

运行测试：

    npm test

## 部署

第一次上线或数据表变化时：

    npm run db:remote
    npx wrangler secret put HOST_RECOVERY_CODE
    npm run deploy

`wrangler.jsonc` 已配置 `debate.ducenhan.com` 自定义域名和独立 D1 database id。根目录 PNYL 首页已把这个地址放在导航与活动列表的第一项。

## 现场带领提醒

- 票数不是自动选题器；主持人仍需考虑题目是否适合当晚成员。
- 至少一人完成站队后即可发放任务；不强迫两边人数平均。
- 不为了凑反方而派人假装支持；若一边无人，可以先讨论什么变化会令人换边。
- 不点名要求成员分享现实中的创伤、财务、家庭或感情经历。
- 总结页不宣布标准答案，也不选获胜方。
