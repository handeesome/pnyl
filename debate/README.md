# 两边之间

这是一个给小型团契用的讨论页面。至少 2 人就能开始，不设人数上限；6–8 人通常最适合分组。活动不分输赢，也不要求大家公开自己真正赞成哪边。每个人会暂时帮其中一边说话，先把两边都听明白，再看看不同情况会不会改变选择。

页面由一台投影电脑主持，不需要参与者使用手机，也没有账号、后端、计分或联网数据。

## 活动流程

1. 全组从十个问题中口头商量并选择一题。
2. 主持人输入至少 2 个名字，页面随机分成两组，每组负责一种说法。
3. 每人获得一个帮助本方立论的任务：找经文依据、举本方的例子、说明本方帮助了谁，或为本方补上界线。
4. 两组分别准备本方的合理理由；需要时可展开经文入口。
5. 两组依次分享，不计分，也不选获胜方。
6. 逐张揭示三个只改变一件事的情境；两组判断自己仍然坚持本方，还是需要承认一个例外，并用一句话说明原因。
7. 分组结束，大家说回自己的想法。
8. 查看预先写好的总结、经文与延伸阅读。

页面只显示柔和的建议时间，不倒数、不响铃，也不会自动切换阶段。主持人使用底部按钮或键盘左右方向键推进。

## 文件结构

```text
debate/
├─ index.html   # 页面入口和固定外壳
├─ styles.css   # 投影布局、响应式样式与视觉主题
├─ app.js       # 分组、角色、阶段导航和本地状态
├─ topics.js    # 十个主题的全部讨论内容
└─ README.md    # 项目说明
```

## 题目内容

每个主题在 `topics.js` 中包含：

- 两边分别怎么想，以及各自最有道理的说法
- 至少三处经文入口及阅读提示
- 三个每次只改变一件事的小情境
- 敏感话题的主持提醒
- 常见基督徒思路、双方优势与极端风险
- 哪些情况会改变选择、两边可以怎样一起考虑，以及最后仍要自己判断的地方
- 可继续阅读的外部来源

修改或新增题目时，不要故意把任何一边写得很蠢。经文是用来帮助大家思考的，不是某一边用来压过对方的武器。小情境每次只改一件事，也不要靠故意隐瞒或极端故事逼大家改变答案。

## 分组与角色

- 页面始终尽量平均分成两组；例如 3 人分成 2 + 1，5 人分成 3 + 2，7 人分成 4 + 3。
- 四人组使用四个独立任务：找经文依据、举本方的例子、说明本方帮助了谁、为本方补上界线。
- 三人组使用“找经文依据”“这一边帮助了谁”“别把话说太绝对”；每项任务都先帮助自己这一边把话说清楚。
- 一至二人组只使用部分任务；超过四人的小组会有人拿到相同任务。
- 随机分组后，可以先点击一名成员的“选择交换”，再点击任意另一名成员完成互换；既可以跨组交换，也可以在同组内交换角色顺序。再次点击已选中的成员会取消选择。
- 角色只是观察角度，不是正式辩论的一辩、二辩，也不规定发言顺序。

## 状态保存

主题、名单、分组、角色、当前阶段和经文展开状态都保存在当前浏览器的 `localStorage` 中，key 是：

```text
pnyl-between-sides-v1
```

刷新页面会恢复当晚进度。换浏览器或换电脑不会同步。右上角“重新开始”会先要求确认，再清除本机活动状态。

页面不会询问或上传你真正赞成哪边。这个答案只留在你自己心里。

## 本地运行

页面使用原生 ES modules，建议通过本地静态服务器运行，而不是直接双击文件：

```powershell
cd C:\Users\ducenhan\Desktop\信仰大富翁
python -m http.server 8765
```

然后打开：

```text
http://127.0.0.1:8765/debate/
```

也可以随现有父项目直接发布到 Netlify 或其他静态站点服务。公开路径为 `/debate/`，父目录的 `index.html` 已包含入口。

## 现场使用建议

1. 活动前在投影电脑打开页面并测试全屏显示。
2. 提前看一遍当晚可能选择的题目、经文和主持提醒。
3. 正式开始前点击“重新开始”，避免恢复上一次的名单和进度。
4. 随机分组后检查表达能力是否过度集中，必要时交换成员。
5. 情况变化阶段一次只看一张卡，不要提前说出后面的内容。
6. 遇到饶恕、心理健康或家庭边界等题目，不要求成员公开创伤、病史或家庭隐私。
7. 总结页只是帮大家收重点，不是唯一标准答案。

## 这个页面不会做什么

- 不做比赛、计分、投票、排行榜或胜负判定。
- 不收集个人真实立场或活动后的个人反思。
- 不做账号、多人同步、云端房间或长期讨论记录。
- 不用现成论据取代参与者的思考；准备阶段只提供可选经文入口。
